# 009jev：Jev-guided native SLA

[English](009JEV.en.md) · 实验分支 `exp/jev-adaptive-vsa`

**009jev 已作为本分支的正式实验方法收录。** 保留常规的 MiniMax H3 模型加载、线性计算与 FastVAE，并从首步起由 Jev 选择标准 SLA 的逐层 keep 率。节点 ID 为 `H3JevNativeSLAPatch`，显示名称为 **009jev: Jev-guided Native SLA**。它与旧的 W4A4/VSA 控制是不同路径，不使用 FC1 W4A4 转换、preconverted gate 或 VSA cube tiling。不并入 main。

## 所需环境

已在 Linux（aarch64）/ NVIDIA GB10 / ComfyUI 0.36.0 上实际生成验证。确认过的 ComfyUI commit 为 `7a0b5eede3f9721c8faab290689893f36edc6d66`。使用内部 API `comfy_extras.nodes_sparse_attention`、native MiniMax H3 的 50 个 blocks，以及 comfy-kitchen 的 SLA 路径。不面向其他模型或任意 sampler。**仅限 4step / res_multistep** 使用。

示例的常规模型为 `minimax_h3_fused_refdelta_r1024_turbo8_mystic07_int8_convrot.safetensors`、32B Qwen encoder、H3 video/audio VAE。准确名称请参考示例中的 node127/128/119/120。权重不随附，也不会自动下载。

示例中的 ChunkFFN 需要 [KJNodes](https://github.com/kijai/ComfyUI-KJNodes)，FastVAE 需要 [MotionCache-FastVAE](https://github.com/Mozer/ComfyUI-MiniMax-H3-MotionCache-FastVAE)。不使用 MotionCache 的输出复用。

## 安装：无需权重转换

请将本分支 clone 到现有专用 ComfyUI 的 custom_nodes 中。如果已存在同一仓库，请不要重复 clone，而是将该副本更新到本分支。

```bash
# 工作目录：目标 ComfyUI 的 custom_nodes
git clone --branch exp/jev-adaptive-vsa --single-branch https://github.com/sepiablue-ai/ComfyUI-MiniMax-H3-W4A4-VSA.git
cd ComfyUI-MiniMax-H3-W4A4-VSA
python3 -m venv .venv-jev
.venv-jev/bin/pip install -r requirements-jev.txt
```

采用这种方式，SDK 只会安装到专用 venv 中。**如果只使用 009jev，则无需运行面向 W4A4 的 setup_env.py 或 convert.py**。这些工具属于旧路径，会要求 gate 和转换。现有 installer 的分发内容中已包含新模块，但 installer 本身仍是 W4A4 用途。

重启 ComfyUI，将节点的 `sdk_python` 指定为专用 venv 中 Python 的绝对路径。留空会使用 ComfyUI 自带的 Python，因此如果将 SDK 安装到了单独的 venv，请务必指定该路径。API key 仅从 ComfyUI 启动进程的 `TYPESAFE_API_KEY` 环境变量获取。请参考[不将 key 写入文件或历史记录的启动示例](JEV_ADAPTIVE.md#不把-api-密钥写入文件直接启动)。不要把 key 写进工作流或代码中。key 缺失、Python 路径无效会在运行前报错。

由于是 **API 格式**，与通常的 GUI 用 JSON 不同。请将自己的 3 张参考图片准备为 `ComfyUI/input/jev_reference_01.png`〜`03.png`，或修改 LoadImage 的名称。顺序为同一人物的全身、上半身、脸部。模型/VAE/encoder 名称也请改为本地实际的文件名。图片与模型的权利请遵守各自的条件。

设置 Jev 版 node900 的 `sdk_python` 并发送到已有 ComfyUI 的示例：

```bash
# 将 node900 的 sdk_python 指向专用 venv，并向已启动的 ComfyUI 提交一次
python3 - <<'PY'
import json, urllib.request
with open('examples/009jev_4step.api.json', encoding='utf-8') as f:
    graph = json.load(f)
graph['900']['inputs']['sdk_python'] = '/absolute/path/to/.venv-jev/bin/python'
req = urllib.request.Request(
    'http://127.0.0.1:8188/prompt',
    data=json.dumps({'prompt': graph}).encode('utf-8'),
    headers={'Content-Type': 'application/json; charset=utf-8'})
print(urllib.request.urlopen(req).read().decode('utf-8'))
PY
```

端口请与已启动的 ComfyUI 保持一致。此示例只提交一次。请记下返回的 prompt_id，并在收到完成通知后查看历史记录。不要以响应不确定为由重复提交同一任务。

更换新的 prompt 时，请将生成节点 131 的 prompt 和 node900 的 `prompt_context` 改为相同的正文。如果历史统计数据的来源或条件不同，也请替换 `initial_context`，或使用 cold-start 示例。不要把旧的统计数据当作当前的观测结果。`prompt_context` 优先于 `initial_context.prompt`。

## Jev 决定的内容

Jev 选择各层的 **1/3/5/10% keep 率**，具体的 attention 连接由 SLA 选择。首次调用传入 prompt 和可选的历史统计数据，一次性判断全部 50 层。第 0 层的首次候选为 5/10%。这并非预读当前画面或首次残差，也没有额外的 probe forward。

在第 2〜4 step，从上一 step 的音频/视频各自的 64token×16channel 中传入相对残差、层内排名、残差的 step 间变化。判断 49 层（1〜49），第 0 层固定为 5%。**模型每个 step 都会执行全部 50 层**。图中只显示 49 层是显示范围的缘故。

首次 confidence 低于 0.3 时回落到 10%，后续阶段回落到 5%。API/回答验证失败时触发回路熔断（circuit breaker），首次失败维持 10%，后续失败维持 5%。SDK 为 jev-1.13.0，timeout 20 秒，retry 0，4step 最多调用 4 次。`fixed5`/`fixed10` 是**仅限首次**的诊断模式，后续仍会调用 API。常规的 009jev 使用 `jev_first`。

音频 query 和条件 KV 等由 SLA 侧另行保护，keep 1% 并不等于总计算量的 1%。SLA 的内部统计状态使用标准实现，但不是复用过去 block 输出的 activation cache。未传入直接评估文字缺失或音质的 OCR/MOS。

发送给 API 的是 prompt 正文、所提供的历史统计数据、聚合后的层统计等。不发送原始图像、音频或模型权重。日志 `[009jev]` 包含判断 state、回答和 usage，因此 prompt 内容也会留在日志中。不记录 API key 和 HTTP 异常正文。

## 采用的实测结果

|相同条件、各 1 次|完整生成|显示时间|
|---|---:|---|
|matlow fused 4step|366.720秒|06:07|
|009jev|213.890秒|03:34|

NVIDIA GB10、1024×1792、124f/24fps、seed2026、4step。缩短 41.675%。包含模型加载、Jev 等待、VAE 和保存。**这是 SLA＋Jev 方式整体的效果，并非衡量 Jev 相对于固定 SLA 单独优势的数值。** 质量等同性尚未认定。

由于旧的"伸手"prompt 出现了多余的手指，按用户指定改为"放下手并点头"的 prompt，并用两种方式重新生成。采用条件与排除经过记录在[实测 JSON](docs/009jev/measurements.json)中。不随附模型、参考图片和视频。
