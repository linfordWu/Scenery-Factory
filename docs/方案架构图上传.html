      03 / ASSET INGESTION

      素材导入与生成共用一个资产系统

      每个素材明确来源与用途。优先使用用户导入且满足条件的素材，只有缺口才生成；成片片段可以绕过 H3 渲染，但仍需经过质检。

      拖拽 / 批量上传→上传会话与文件校验→去重 / 媒体探测→代理预览与索引→绑定角色 / 场景 / 镜头
      素材类型用户可以做什么在生产线中的去向
      剧本 / 文本上传或粘贴已有剧本，修改场次和对白。解析为 Script，交给分镜与连续性 Agent。
      图片导入角色定妆照、服装、场景图、首帧或尾帧。AssetBinding → 画布与视频条件；缺失时调用 Qwen Image。
      视频作为角色/运动参考，或指定时间范围直接复用为镜头。参考模式按能力表接入；直接复用则裁剪/标准化 → 质检 → 接受。
      音频 / 字幕导入台词、配音、配乐、字幕与时间轴。生成条件（能力支持时）或后期素材；检验时间轴与音画一致性。

      资产字段

      asset_id / project_id / source / media_type / sha256 / version / metadata / storage_key / preview_key

      source = imported | generated | derived。衍生物记录 parent_asset_ids；关联表保存角色、镜头、用途和视频裁剪范围。

      原件不可变；转码与裁剪生成新资产。READY 代表处理完成，不代表通过镜头质量验收。

      导入实现约束

      • 支持分块、续传、提交后校验校验和。
      • 使用服务端 Asset ID / 存储键，不接受客户端任意绝对路径。
      • 文件探测、缩略图和代理转码在后台执行。
      • 去重不丢失项目权限、来源和角色绑定。
      • 浏览器所在电脑的路径不能当作 GB10 文件路径。
      UPLOADING → VALIDATING → PROCESSING → READY / FAILED
      READY → 参考输入 → 生成 → 质检
      READY → 直接复用片段 → 标准化 → 质检 → ACCEPTED
      04 / SMALL MODEL ROUTING

      Jev / Laya：辅助决策，加速端到端生产

      本地默认候选

      Laya Decision Worker

      Laya 提供面向文本/JSON 的 choice、score、noul 决策。项目提供本地权重与多语言路径，可用于有限选项路由；中文状态优先验证多语言版本。其文档提示领域适配和置信校准仍然必要。

      依据：Laya 项目文档与能力边界。不将官方其他硬件的速度数字套用到 GB10。

      保留适配接口 · 默认关闭

      Jev-compatible Decision Port

      TypeSafe 官方将 Jev 定位为结构化决策模型，当前官方页面展示服务/API 接入。此次未核实到可下载的本地权重；在你的全本地约束下，Jev 仅保留接口位置，实际执行优先验证 Laya。

      依据：TypeSafe 官方介绍、官方 API 文档。

      规则排除不可执行项→压缩状态 + 候选集合→Laya 结构化建议→校验 / 校准阈值→执行或回退 Qwen
      调用位置小模型辅助判断潜在收益与边界
      素材准备前根据素材元数据和 VLM 描述，建议复用、补图或补充输入。有望减少重复生图；哈希去重和版本一致性仍由代码确定。
      视频生成前从已验证的文生/图像条件/参考模式及参数档位中选候选。有望减少大模型路由调用；不能创造 H3 不支持的模式。
      质检失败后按证据建议“改提示词 / 换素材 / 改分镜 / 人审”。有望减少无效重试；不能直接读视频或豁免质量规则。
      队列调度辅助在硬依赖与优先级允许的候选中提供批处理建议。减少加载切换的效果需实测；GPU 租约和最终调度由程序控制。
      加速指标是“每条合格视频的总耗时与重试次数”。Laya 不直接减少 H3 的扩散步数；决策概率也不等于视频质量分。样片升级为高质量视频后，必须重新质检。
      DecisionAdvice 应用层协议（建议设计，不是官方 SDK 参数）

      不要要求 Laya 输出长篇推理或替代提示词生成。输入必须包含有效的短状态与少量合法候选；缺证据、超出上下文、异常或低置信时，回退规则/Qwen。解释文案由所选动作、规则和证据引用生成。

      先以影子模式运行：保存建议但不影响任务；用独立中文镜头样本校准后逐步启用。优先实测 CPU，只有端到端收益明确时才占用 GB10 GPU。

      05 / DESIGN REVIEW

      方案审查：本轮修正的关键问题

      已补全设计导入素材缺少一等入口

      新增上传会话、处理状态、用途绑定、版本和来源。可复用视频直接走质检，避免不必要地重新生成。

      已调整优先级Web 不应等到最后才建设

      首个开发切片就包含上传、镜头列表和事件流；每个后端步骤都能在浏览器中定位执行者与结果。

      已修正恢复语义请求重发与新一轮生成混淆

      用 command_id 区分网络重发，用 attempt_id 区分主动重生成。输入哈希用于追溯/缓存，不替代业务幂等。

      已补充可靠性队列与进度缺少持久化事件

      状态更新与 Outbox 同事务，去重发布事件；SSE 支持游标回放。GPU 租约失效需核实旧进程，而非立即再占用。

      需实机验证小模型不自动带来渲染加速

      Laya 只优化有限决策与失败分流；先验证中文领域准确率、校准和端到端收益。Jev 不默认接入离线链路。

      已加强验收样片通过不能代替成片通过

      导入、标准化、高质量重渲染均可能改变输出；按最终产物重新评分，只有被接受的版本参与合成。

      06 / RESPONSIBILITIES

      Agent 与服务职责

      Agent 是共享结构化状态的角色任务；同一文本模型可以轮流执行这些任务。生成、排队、状态转换和放行由服务执行。

      模块输入 → 输出实现归属开发边界
      Web 工作台 / 资产接入用户命令、文件 → UploadSession、AssetBinding、任务视图Web 前端 + FastAPI + 素材 Worker前端不直连模型；通过事件流观察并操作任务。
      小模型辅助决策短文本状态、合法动作 → DecisionAdvice本地 Laya；Jev 仅保留接口领域验证、置信校准、规则校验；异常回退。
      制片 / 编剧 Agent主题、时长、风格 → Brief、剧本、场次本地 Qwen 文本模型校验剧本长度、镜头预算和角色 ID。
      分镜 / 连续性 Agent剧本、角色状态 → ShotSpec、连续性约束本地 Qwen 文本模型 + 规则每个镜头明确动作、构图、台词和必须出现的元素。
      视觉资产服务角色与场景定义 → 参考图、关键帧Qwen Image 2.1 7B（按用户配置名）导入与生成共用资产接口；先复用，再补缺口；批准资产固定版本。
      提示词优化 AgentShotSpec、历史失败 → PromptSpec本地 Qwen 文本模型仅修改允许字段；保留失败前后的差异。
      工作流编译与渲染PromptSpec、参考资产 → RenderRequest、VideoAssetComfyUI Adapter + MiniMax H3使用实机导出的 API 工作流；模型支持的输入由能力表确定。
      评分服务候选视频、验收标准 → ScoreReport、证据片段本地视觉理解模型 + 视频/音频检测工具不把图像生成模型当成视频理解模型；不确定结果转复核。
      修复 Agent失败报告、历史尝试 → RepairPlan本地 Qwen 文本模型返回修改方案，由规则校验后执行；重试预算不可绕过。
      编排 / 剪辑 / 导出状态事件、接受的镜头 → 成片、清单FastAPI、任务队列、PostgreSQL、FFmpeg只选 accepted_run_id；整片再验收后交付。
      模型命名说明：保留你提供的 Qwen 文本模型、Qwen Image 2.1 7B 和 MiniMax H3 名称。开发前把实际仓库 ID、权重版本、量化方式、许可证与输入能力写入配置；本页不将模型名称视为 GB10 已通过兼容性验证。
      07 / CONTRACTS

      接口与数据结构

      项目统一状态

      数据库是事实来源。模型上下文从已保存状态构建，避免角色任务各自维护冲突的“记忆”。

      • Project / Scene / Shot：层级、风格与镜头规格。
      • Character / Asset：角色身份、服装、素材版本和摘要。
      • Run：单次执行输入、模型版本、seed、外部任务 ID。
      • ScoreReport / RepairPlan：分数、证据、修复差异。
      • StepRun / Event / Outbox：步骤执行者、工具调用、进度、事务事件及重试原因。
      • UploadSession / AssetBinding / DecisionAdvice：分块上传、素材用途、模型建议与规则执行记录。

      幂等、恢复与版本

      • 请求重发复用 command_id；主动再生成使用新命令和 attempt_id。
      • Run 与 Outbox 同事务登记；提交渲染后关联 prompt_id，模糊结果先对账。
      • 输入哈希包含模型/工作流版本、素材版本、参数与 seed；缓存匹配仍需验证当前验收规则。
      • 修复创建新 Run；保留旧视频及输入用于比较。
      • 角色或场景版本变化时，标记依赖镜头待复核。

      POST /assets/uploads/{id}/complete提交上传并后台处理asset_id、processing_job_id
      POST /shots/{id}/asset-bindings绑定参考素材或复用片段role、asset_version、clip_range
      POST /runs/{id}/commands暂停、恢复、取消和主动重试command_id、expected_state_version
      GET /runs/{id}/steps查看步骤、执行者、调用与产物StepRun[]、trace 引用
      POST /projects创建项目与生产约束project_id、schema_version
      POST /projects/{id}/plan生成剧本、场次与分镜job_id；异步任务
      POST /shots/{id}/runs提交一个镜头的生产任务run_id；需要幂等键
      GET /runs/{id}查询阶段、候选资产与评分state、artifacts、score、failure

      08 / QUALITY LOOP

      评分、修复与状态机

      PLANNED → ASSET_READY → PROMPT_READY → QUEUED → RENDERING → GENERATED → SCORING → ACCEPTED
      素材复用路径：ASSET_READY → NORMALIZING → SCORING → ACCEPTED
      SCORING → REPAIRING → PROMPT_READY / ASSET_READY
      预算耗尽或评分不确定 → HUMAN_REVIEW　｜　执行异常 → RETRY_WAIT / FAILED

      1. 文件与技术检查

      用确定性工具验证文件可解码、分辨率、时长、音轨、黑屏及重复帧。检测结果和阈值进入报告。

      角色数量、身份和水印识别属于语义检测，不能宣称仅靠文件规则可靠判断。

      2. 语义与时间维度

      以角色参考图、ShotSpec、均匀采样帧及关键动作片段为输入，检查身份、动作、场景、连续性与音画要求。

      抽帧无法保证发现全部瞬时问题；不确定时追加片段检查或转人审。

      3. 决策与预算

      验收规则显式版本化；关键要求不通过就拒绝。总分只用于排序候选，不能抵消关键项失败。

      0.85 等阈值是试验起点，不是准确率承诺。先用标注样本校准。

      失败标签修复动作重新执行起点
      identity_drift / costume_mismatch检查角色素材版本；更换批准的参考图；选择实机支持的参考工作流。ASSET_READY 或 PROMPT_READY
      action_incomplete减少动作数量；明确动作先后；必要时将复杂镜头拆开。分镜重规划 → PLANNED
      composition_mismatch重新生成构图锚帧；再执行图像条件的视频工作流。ASSET_READY
      flicker / deformation调整运动、片段长度和已验证的采样配置；记录新旧参数。PROMPT_READY
      dialogue_mismatch / audio_issue校验台词、音轨与授权声音资产；按实际能力重生成或独立后期。渲染或音频后期
      OOM / timeout / worker_crash先核实或终止旧进程，确认资源释放；增加 fencing token 后再排队；拒绝旧尝试的迟到结果。基础设施重试，不记作创作评分失败

      建议初始预算：首轮 + 最多 2 次自动修复；另设累计执行时长上限。超过预算进入人审，保存最佳候选但不自动当作合格成片。

      09 / LOCAL RUNTIME

      GB10 本地部署设计

      先采用单机、单个重型推理任务的调度方式。文本、图像、视频、评分与小模型辅助决策 Worker 是逻辑职责，可以共享一个进程池与 GPU 租约；无需同时把所有模型加载进内存。

      建议 MVP 组合

      • Web 前端：项目、素材、画布、视频生成和任务监控，作为首个交付入口。
      • FastAPI：业务 API、鉴权与可回放事件流。
      • PostgreSQL：持久化状态、版本和任务事件。
      • Celery + Redis：执行任务与排队；数据库保存权威状态。
      • 本地文件目录：素材存储，通过 AssetStore 接口读写。
      • ComfyUI：执行已冻结并验证的工作流。
      • FFmpeg / ffprobe：抽帧、音视频检查与合成。

      任务规模扩大后再按需求替换为 Temporal、对象存储或多机 Worker。

      GB10 资源管理

      • 依次实测文本、图像、视频、评分与 Laya；小模型先评估 CPU 路径。
      • 记录加载时间、峰值内存、单镜耗时与失败率。
      • 重型推理执行前申请独占租约；心跳与 fencing token 防止重复占用和迟到提交。
      • 阶段切换时卸载模型并确认资源释放。
      • 按模型批处理可减少加载开销；不破坏镜头依赖。
      • 验证 ARM64、驱动、PyTorch 与自定义节点的兼容性。

      ComfyUI 接入顺序

      1. 在 GB10 手动跑通所需模型的最小工作流，再导出 API JSON。
      2. 定义允许替换的输入：提示词、素材路径、seed、尺寸与时长。根据实际节点映射，不硬编码未经验证的节点名。
      3. Adapter 校验输入、注入参数并提交；记录返回的任务标识。
      4. 读取进度与历史结果，验明输出文件完整后登记 Asset；API 细节以安装版本为准。
      5. 将工作流哈希、模型配置、所有条件输入和输出一起记录到 Run。
      10 / BUILD PLAN

      开发实施步骤与验收标准

      按交付物推进。先证明单镜头链路可运行、可恢复，再扩展到整集和全自动处理。

      01

      Web 项目骨架与素材导入

      先实现项目、素材库、镜头列表，配合 API、Asset Store 和上传后台任务；同时在 GB10 验证实际权重与工作流。

      验收：浏览器可上传图片/视频、预览处理状态并绑定镜头；模型有真实冒烟输出。
      02

      步骤状态、事件流与控制命令

      建立 Run、StepRun、Event、Outbox；Web 展示步骤、执行者与产物。实现 command_id、状态版本及 SSE 回放。

      验收：刷新/断网重连后恢复相同任务；重复命令不会创建重复执行。
      03

      本地 H3 渲染与素材复用双路径

      封装 ComfyUI 模板；图像参考进入生成，导入视频可直接标准化并评分；记录外部任务 ID 与 GPU 租约。

      验收：网页能看到真实执行进度；重复视频不强制生成；提交超时可以对账。
      04

      分镜 Agent、场景画布和缺口生成

      接入 Qwen 结构化分镜和可编辑画布，建立角色与场景版本。导入优先，缺少素材时再用 Qwen Image。

      验收：五镜头项目可混用导入/生成素材，素材替换后只标记受影响的依赖。
      05

      独立质检与最终产物验收

      建立人工标注集，验证技术检测、视觉评估与证据。Web 可并排查看候选、评分和失败片段。

      验收：报告误放/误拒率；导入片段与高质量重渲染产物都再次验收。
      06

      Laya 影子评估与有限自动路由

      实现 DecisionPort 与本地 Laya；只记录候选选择，先不改变执行。验证中文场景、校准与资源开销，再启用合格策略。

      验收：质量不降低的前提下证明决策耗时/重试次数收益；低置信和服务故障可回退。
      07

      修复闭环、成片合成与恢复测试

      接入差异化修复、预算、人审和 FFmpeg 成片；验证暂停、取消、Worker 崩溃、事件重放与迟到结果拒绝。

      验收：可交付混合素材样片；端到端每步可观察、可追溯、可恢复。
