## 2. 冠军叙事主线

本项目要讲清楚一句话：**Fusion Xpark GB10 不只是一个能跑大模型的设备，而是可以成为本地内容生产的调度中心。**

传统 AI 视频 Demo 通常停留在“输入 prompt，输出视频”。真实短视频生产却需要处理更多问题：用户已有素材如何复用？角色和场景如何保持一致？失败后如何修复？每个镜头为什么合格？人工审核如何介入？任务中断后如何恢复？本项目把这些生产问题纳入同一条流水线，并用状态机、事件流、结构化分镜、质量报告和修复预算形成闭环。

## 3. 差异化创新点

### 3.1 从生成工具到生产系统

项目将 Web 工作台作为首个交付入口，而不是事后补一个展示页。用户能看到项目、素材、镜头、任务、执行者、事件、质检证据和最终成片。这个设计把“模型生成结果”变成“可审计生产过程”。

### 3.2 主 Agent 可插拔，StepFun 作为首选配置

主 Agent 承担制片、编剧、导演、提示词优化和修复建议等文本推理任务。项目将其抽象为 OpenAI-compatible provider，赛事推荐配置使用 StepFun 阶跃星辰；在未配置 StepFun endpoint 或密钥时，也可以切换到其他 provider。这样既满足平台适配要求，又避免把系统锁死在单一模型上。

### 3.3 多智能体协同不是角色扮演，而是契约协作

制片、编剧、选角、导演、提示词优化、审核和修复 Agent 共享同一套 ShotSpec、ScoreReport、RepairPlan 与事件流。每个 Agent 的输出都会被代码校验和状态机约束，避免多 Agent 系统常见的上下文冲突和不可控输出。

### 3.4 模型优化落在端到端生产指标上

009jev Native SLA、Laya 本地决策和 OpenJev 实验路径不是孤立的模型技巧，而是服务于“每条合格视频总耗时”和“无效重试次数”两个生产指标。当前 Fusion Xpark GB10 Linux 实测中，Laya 路径将 5 秒 4 step 热缓存视频从 530.2 秒降至 340.1 秒。

### 3.5 Agent Skills 把经验变成资产

`deploy-scenery-factory` 把一次从零部署固化为可复用 skill（环境自检 → 装依赖 → 配 `.env` → 启动 → 验收），让任意 Agent 都能把本项目部署成短剧 Agent 工厂；`learning-video` 将文档到学习视频的流程沉淀为可复用 skill；`short-drama-script` 将短剧剧本与分镜约束沉淀为可复用 skill。Skills 不只是说明文档，而是项目持续扩展能力的接口。

## 4. 面向评审的证据路径

建议评审按以下顺序查看：

1. 先看本文件，理解项目如何逐项回应评分标准。
2. 再看 [01-项目说明文档](01-项目说明文档.md)，理解痛点、方案、架构和优化。
3. 按 [02-Fusion Xpark GB10-Linux部署说明](02-Fusion-Xpark-GB10-Linux部署说明.md) 复现 Fusion Xpark GB10 Linux 部署。
4. 按 [05-演示视频脚本](05-演示视频脚本.md) 观看或录制 Demo。
5. 最后查看仓库根 `apps/`、`agents/`、`workers/`、`adapters/`、`domain/`、`skills/` 与 `tests/`，确认工程完整性。

当前真实部署核验入口为 `http://localhost:8188`（ComfyUI）与 `http://localhost:8600`（短视频工厂启动后）。

## 5. 不夸大、可验证的表述边界

- StepFun 是主 Agent 的首选赛事配置，代码通过可插拔 provider 接入；实际 endpoint、模型名和密钥不写入仓库。
- Fusion Xpark GB10 性能数字来自当前仓库与当前输入条件，不代表所有工作负载的固定结果。
- Laya / OpenJev 决策是生产辅助，不替代质量验收。
- 模型权重、参考图片、生成视频和密钥不随仓库分发。
